# 技术方案（主 App · B4 单词记忆）

## 1. 架构分层

```
UI (Fragment + ViewBinding)
  ↓ 事件 / StateFlow
ViewModel（状态持有，无 Android Context 依赖）
  ↓
Repository（WordRepository / ReviewRepository / SettingsRepository）
  ↓
Room DAO  ·  DataStore  ·  SAF 文件读取  ·  WorkManager
```

- 单 Activity + Navigation（`nav_graph.xml`），页面间用 `SafeArgs` 传参。
- 依赖注入：先手写 `AppContainer`（避免过早引入 Hilt），后期可选迁移。
- 线程：Room/文件 IO 走 `Dispatchers.IO`；算法为纯 Kotlin，可在 JVM 单元测试中直接测。

## 2. 数据模型（Room）

```kotlin
@Entity(tableName = "deck")
data class Deck(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val name: String,
    val createdAt: Long = System.currentTimeMillis()
)

@Entity(
    tableName = "word",
    foreignKeys = [ForeignKey(Deck::class, ["id"], ["deckId"], onDelete = CASCADE)],
    indices = [Index("deckId"), Index("nextReviewAt")]
)
data class Word(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val deckId: Long,
    val text: String,          // 单词
    val phonetic: String?,     // 音标
    val meaning: String,       // 释义
    val example: String?,      // 例句
    // ---- SRS 状态 ----
    val repetition: Int = 0,   // 连续答对次数
    val easeFactor: Double = 2.5,
    val intervalDays: Int = 0,
    val nextReviewAt: Long = System.currentTimeMillis(),
    val lastReviewAt: Long? = null
)

@Entity(tableName = "review_record")
data class ReviewRecord(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val wordId: Long,
    val reviewedAt: Long,
    val grade: Int,            // 0 不认识 / 1 模糊 / 2 认识
    val mode: String           // "review" | "quiz"
)
```

统计查询（`@Query` 聚合，避免全表加载）：

```sql
SELECT COUNT(*) FROM word WHERE nextReviewAt <= :now;
SELECT COUNT(DISTINCT date(reviewedAt/1000,'unixepoch','localtime')) FROM review_record WHERE reviewedAt >= :since;
```

## 3. SRS 调度算法（自定义，核心评分点）

简化 SM-2，三档反馈映射为质量分 q：不认识 = 2，模糊 = 3，认识 = 5。

```
fun schedule(word, grade, now):
    q = when(grade) { FORGOT -> 2; VAGUE -> 3; KNOWN -> 5 }

    if (q < 3) {                       // 忘了：重置进度，10 分钟后重来
        repetition = 0
        intervalDays = 0
        nextReviewAt = now + 10.minutes
        easeFactor  = max(1.3, easeFactor - 0.2)
        return
    }

    repetition += 1
    intervalDays = when (repetition) {
        1 -> 1                          // 第 1 次答对：明天
        2 -> 3                          // 第 2 次：3 天后
        else -> round(intervalDays * easeFactor).coerceIn(1, 180)
    }
    easeFactor = (easeFactor + (0.1 - (5 - q) * (0.08 + (5 - q) * 0.02)))
                    .coerceIn(1.3, 2.8)
    nextReviewAt = now + intervalDays.days
```

- 纯函数 `SrsScheduler.schedule(state, grade, now)`，输入输出都是数据类，**无副作用**，便于单元测试。
- 单元测试覆盖：首次答对、连续答对递增、遗忘重置、EF 上下界、跨月跨年时间计算（`Clock` 注入，不用 `System.currentTimeMillis()`）。

## 4. 通知与后台任务（强制技术点）

- 每日提醒：`PeriodicWorkRequest(24h)` + 首次 `OneTimeWorkRequest` 计算到下一个提醒时刻的延迟；`ExistingPeriodicWorkPolicy.UPDATE`。
- 提醒内容：`今日还有 N 个单词待复习`（N 来自 Room 查询）。
- 通知 Action（`PendingIntent` → `BroadcastReceiver`）：
  - 「开始复习」→ 深链进复习页；
  - 「稍后 10 分钟」→ 重新入队一次性任务；
  - 「今日免打扰」→ DataStore 写入 `snoozeUntil = 明日 0 点`。
- Android 13+ 权限：`POST_NOTIFICATIONS` 运行时申请；拒绝 → 首页横幅 + 红点，功能不受限（降级路径，验收必演示）。
- 精确时间：需分钟级精度时用 `AlarmManager.setExactAndAllowWhileIdle` + `SCHEDULE_EXACT_ALARM` 检查，否则退化为 WorkManager 近似调度。

## 5. 关键 UI 设计

- 复习卡片：`MaterialCardView` + 翻转动画（`rotationY` 属性动画）；三档按钮固定底部，防误触。
- 统计柱状图：自绘 `View`（`onDraw` + `Canvas.drawRoundRect`），7 天数据来自 DAO。
- 空态：`StateLayout`（loading / empty / error / content 四态）在各列表页复用。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 导入文件格式不统一 | 先只支持 CSV + 固定 JSON schema，界面上给出模板下载 |
| 通知在工作日/周末行为不同 | 设置页提供「仅工作日」开关，DataStore 存储 |
| 复习队列过长导致体验差 | 每日上限 + 「先复习逾期最久的」排序 |
| 时间与时区变化导致到期计算错误 | 统一存 UTC 毫秒时间戳，展示时用 `LocalDate` 本地化 |
| 伴生模块与主 App 数据库耦合过紧 | 伴生模块只读 DAO，写操作全部走主 App |
