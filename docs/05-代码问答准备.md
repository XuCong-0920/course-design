# 代码问答准备（答辩抽查用）

> 课程验收会当面问「这段为什么这么写」。下面按「老师最可能问的」排序，每题给出一句话结论 + 能指向的具体文件/常量。
> 回答原则：先给结论，再给一处**可指认的代码**，最后说取舍代价。

## 一、算法与调度

**1. 为什么用 SM-2 而不是自己拍脑袋？**
SM-2 是被验证过的间隔重复模型，EF（难度因子）让「这个词对我难不难」参与间隔计算。我做了简化：三档反馈映射 q=2/3/5，间隔上限 180 天。
→ `app/src/main/java/com/xucong/wordmemory/domain/srs/SrsScheduler.kt`

**2. 为什么答错只等 10 分钟，而不是明天？**
答错的词如果今天不再出现，用户当天就没有第二次机会；10 分钟是「够忘掉刚才看到的答案、但还在同一次学习会话内」的经验值。同时它不会插回本轮队列，避免连续重刷同一张卡。
→ `SrsScheduler.FORGOT_RETRY_MILLIS`、`ReviewViewModel.grade()`

**3. 间隔为什么夹在 1 到 180 天？**
下限 1 天防止同一天反复刷（把间隔刷成 1 天以内等于没间隔）；上限 180 天防止「背熟了以后再也见不到」。上限用 `coerceIn` 一处收口。
→ `SrsScheduler.schedule()` 内 `coerceIn(1L, MAX_INTERVAL_DAYS)`

**4. 算法层为什么不直接用 WordEntity？**
`SrsState` 是纯数据，算法不依赖 Room/Android，所以能在 JVM 单测里跑（28 个用例不需要模拟器）。Entity 与 SrsState 的转换放在数据层 `WordRepository.submitReview`。
→ `domain/srs/SrsScheduler.kt` 与 `data/WordRepository.kt`

**5. 时间为什么是参数传进来，而不是 `System.currentTimeMillis()`？**
不注入时间就没法断言「跨闰日」「同日第二次」这种场景，测试会变成"跑一次看运气"。
→ `SrsSchedulerTest` 里 `feb28 = 1_709_078_400_000L` 的用例

## 二、数据与事务

**6. 为什么把 SRS 字段塞进 words 表，不单独建一张状态表？**
复习队列的查询是 `WHERE dueAt <= now ORDER BY dueAt`，内嵌字段只需要一次索引扫描；单建表会让每张卡片多一次 JOIN，而这张表没有「多状态」需求。
→ `data/local/entity/WordEntity.kt`

**7. 为什么复习结果必须在一个事务里写？**
要同时改 `words` 的 SRS 字段并插 `review_records`。分开写的话，进程被杀会出现「统计显示背过、调度没推进」或反过来，用户看到的数据就自相矛盾。
→ `WordRepository.submitReview()` 的 `database.withTransaction`

**8. `(deckId, term)` 唯一索引解决什么问题？**
重复导入同一个词库时不会写重复词，配合 `OnConflictStrategy.IGNORE` 天然去重，导入不需要先查再插。
→ `WordEntity` 的 `indices = [Index(value = ["deckId", "term"], unique = true)]`

**9. 词库列表的「今日到期数」怎么来的？会不会 N+1？**
一条 SQL 带两个子查询，一次查出词库 + 单词数 + 到期数，UI 层不做循环查询。
→ `DeckDao.observeSummaries`

## 三、UI 与生命周期

**10. 为什么用 ViewBinding 不用 findViewById / DataBinding？**
类型安全、编译期检查、不需要反射；DataBinding 对这个小项目是额外的心智负担（还要处理表达式与主题）。
→ `app/build.gradle.kts` 的 `buildFeatures { viewBinding = true }`

**11. 收集 Flow 用的是什么作用域？为什么？**
`viewLifecycleOwner.lifecycleScope` + `repeatOnLifecycle(STARTED)`：Fragment 视图销毁就停止收集，避免在后台继续更新已销毁的视图（这是查内存泄漏时最容易出问题的地方）。

**12. 统计页为什么不用 Flow 实时订阅？**
复习时每点一次就写一次库，Flow 会让统计页在后台反复重算整页；统计页停留时间短，`onResume` 时算一次就够。代价是页面不实时刷新，可以接受。
→ `ui/stats/StatsViewModel.refresh()`

**13. 为什么不用 Safe Args，而是 Bundle + companion 常量？**
AGP 9 内置 Kotlin 后，Safe Args 需要额外的 Kotlin 插件与序列化配合，多一个插件就多一层构建风险；这个项目只有两处传参（deckId / deckName），手写常量更透明。
→ `WordListFragment.ARG_DECK_ID`

**14. 底部导航的 item id 为什么和 Fragment 的 id 一样？**
Navigation 的 `setupWithNavController` 靠 id 匹配，id 一致就不用写映射表；改导航图不会出现"点了没反应"。

## 四、构建与工具链

**15. 为什么根 build.gradle 里没有 kotlin-android 插件？**
AGP 9 起内置 Kotlin 支持，再应用 `org.jetbrains.kotlin.android` 会报 `Cannot add extension with name 'kotlin'`。这是本项目真实踩过的坑，写在 README 踩坑记录 1。
→ `build.gradle.kts`、`README.md`

**16. `android.disallowKotlinSourceSets=false` 是干什么的？**
KSP 目前仍通过 `kotlin.sourceSets` 加生成源码，而内置 Kotlin 默认禁止这个 DSL。这个开关是过渡期的妥协，等 KSP 适配后可以删掉。
→ `gradle.properties`、README 踩坑记录 2

**17. Room 的代码是手写的吗？**
不是。`@Entity/@Dao/@Database` 由 KSP 生成 `WordDatabase_Impl` 等实现类，构建产物里能看到，APK 的 dex 里也有。回答时可以指出 `app/build/generated/ksp/...`。

## 五、通知与权限（强制技术点）

**18. 为什么用 WorkManager 而不是 AlarmManager？**
周期任务重启后能自恢复，不必处理 `BOOT_COMPLETED`，也不用申请 `SCHEDULE_EXACT_ALARM`；代价是可能被推迟几分钟，对"每天提醒背单词"够用。要分钟级精确再退化到 `setExactAndAllowWhileIdle`。
→ `notification/ReminderScheduler.kt`

**19. 到期为 0 为什么不发通知？**
空提醒最容易被用户顺手关掉权限，关了就再也不提醒了。所以 Worker 先查 `countDue(now)`，为 0 直接 success。
→ `notification/ReviewReminderWorker.doWork()`

**20. 权限被拒之后会怎样？**
功能全部照常，只是不弹通知；「我的」页有红字提示，并给一个「立即发一条测试提醒」的入口让用户验证。`canPost()` 同时判断运行时权限和系统通知总开关。
→ `notification/ReminderNotifications.canPost()`、`ui/mine/MineFragment`

**21. 通知的三个动作是怎么实现的？**
「去复习」是 `PendingIntent.getActivity` 带 `EXTRA_OPEN_REVIEW`，`MainActivity` 收到后直接选中复习页（`launchMode=singleTop` + `onNewIntent`）；另外两个是 `getBroadcast` 到 `ReminderActionReceiver`，分别入队 10 分钟后的任务、写「今日跳过」标记。

## 六、可能被追问的"没做完"

**22. 词库导入（CSV/JSON）做了吗？**
内置词库已在，文件导入是第 8–9 次课的内容，方案已定：SAF 选文件 → 逐行解析、坏行跳过并汇总 → 事务写入，重复词靠唯一索引忽略。答的时候要主动说"还没做完，方案在这里"，不要装作做完了。

**23. 测试模式为什么不写库？会不会显得功能弱？**
这是刻意设计：测试是自测手段，如果它推进 SRS，用户随手刷十道选择题就能把词刷到 180 天后，"记忆曲线"就失真了。结果页会引导用户去复习页把错词标成"不认识"，决定权交回用户。

**24. 统计里的"连续打卡"怎么算？跨时区会不会错？**
按本地日切分（`Calendar` 取当天 00:00），今天有记录从今天往回数，今天还没有就从昨天往回数（避免早上打开看到 0 天）。全部存 UTC 毫秒、展示时本地化，跨时区只影响"哪一天"的归属，不影响记录本身。
→ `domain/stats/StatsCalculator.streakDays()`

## 七、自测题（能答上来就算过关）

1. `SrsScheduler.schedule(state, KNOWN, now)` 连调三次，第三次的 intervalDays 是多少？（答：8，因为 round(3 × 2.7)）
2. 答错一次后 EF 从 2.5 变成多少？（答：2.4，并且 repetition/intervalDays 归零）
3. 统计页显示的"今天已复习"数量来自哪张表？（答：`review_records`，按 `reviewedAt` 落今天算）
4. 如果把 `PASS_GRADE` 从 1 改成 2，界面哪个数字会变？（答：正确率，"模糊"不再算通过）
